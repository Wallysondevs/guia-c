C Array que Cresce

Um array comum tem tamanho fixo: double precos[5]; guarda cinco preços, nem um a mais. Mas a lista de compras da Ana não tem tamanho fixo: num dia são três itens, no mês de festa são quarenta. Nesta aula você vai juntar o que aprendeu em malloc e free e calloc e realloc para montar um array que cresce sozinho conforme os itens chegam. É uma das peças mais usadas de todo programa em C (e é o que o list do Python e o vector do C++ fazem por baixo dos panos).

Você vai aprender
  • A diferença entre tamanho (quantos itens existem) e capacidade (quantos cabem).
  • Como fazer o array crescer com realloc quando ele lota.
  • Por que crescer dobrando a capacidade é muito melhor do que crescer de um em um.
  • O jeito seguro de chamar realloc (e o que se perde no jeito errado).
  • Como guardar tudo em duas funções, adicionar e liberar.
  • Como ler uma quantidade qualquer de números do teclado ou de um arquivo.
  • Como conferir com o valgrind que nenhum byte vazou.

Todos os programas desta aula foram compilados com o gcc 15.2 na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/c, com o comando padrão do guia: gcc -std=c23 -Wall -Wextra arquivo.c -o programa (veja Compilar com gcc). Você pode repetir cada um no editor do guia.

A ideia: o caderno que lota

A Ana anota as compras num caderno pequeno, de 4 linhas. Enquanto há linha livre, ela só escreve. Quando o caderno lota, ela compra um caderno maior, copia as anotações para ele e joga o pequeno fora. Daí em diante, continua escrevendo no novo.

Repare em dois números diferentes:

  • quantas linhas estão escritas (o tamanho da lista);
  • quantas linhas o caderno tem (a capacidade).

Enquanto o tamanho é menor que a capacidade, escrever é fácil. Quando os dois ficam iguais, é hora de trocar de caderno.

O realloc (de re-allocate, "reservar de novo") faz exatamente a troca de caderno: reserva um bloco maior, copia o conteúdo do antigo e libera o antigo. Às vezes ele consegue até "esticar" o bloco no mesmo lugar, sem copiar nada. Você não precisa saber qual dos dois aconteceu: só precisa usar o ponteiro que ele devolve.

size_t

size_t é o tipo que o C usa para tamanhos e quantidades: um inteiro sem sinal (nunca negativo), do tamanho certo para contar bytes na sua máquina. É o tipo que o sizeof devolve e que o malloc recebe. No printf, o formato dele é %zu. Detalhes em sizeof.

1. A primeira versão: crescer de um em um

Comece com três variáveis: o ponteiro para a memória, o tamanho e a capacidade. No começo não existe memória nenhuma: o ponteiro vale NULL e os dois números valem zero. A cada item novo, se a lista estiver lotada, o programa pede espaço para mais um.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    double *precos = NULL;
    size_t tamanho = 0;
    size_t capacidade = 0;

    double novos[] = {12.50, 4.99, 7.80, 3.25, 9.90};

    for (size_t i = 0; i < 5; i++) {
        if (tamanho == capacidade) {
            size_t nova = capacidade + 1;
            double *maior = realloc(precos, nova * sizeof(double));
            if (maior == NULL) {
                printf("Sem memória!\n");
                free(precos);
                return 1;
            }
            precos = maior;
            capacidade = nova;
            printf("Cresceu: agora cabem %zu\n", capacidade);
        }
        precos[tamanho] = novos[i];
        tamanho++;
    }

    for (size_t i = 0; i < tamanho; i++) {
        printf("Item %zu: R$ %.2f\n", i + 1, precos[i]);
    }

    free(precos);
    return 0;
}
double *precos = NULL;
O "caderno". Começa sem memória nenhuma. Iniciar com NULL é importante: o realloc aceita NULL e, nesse caso, funciona igual a um malloc.
size_t tamanho = 0; size_t capacidade = 0;
Quantos itens estão guardados e quantos cabem. As três variáveis andam sempre juntas: mexeu numa, confira as outras.
if (tamanho == capacidade)
A lista lotou (ou ainda nem existe, quando os dois valem 0). Só nesse caso é preciso crescer.
size_t nova = capacidade + 1;
A nova capacidade: um lugar a mais. (Daqui a pouco você vai trocar esta linha.)
double *maior = realloc(precos, nova * sizeof(double));
Pede um bloco com espaço para nova preços. O tamanho é em bytes, por isso o * sizeof(double). O resultado vai para uma variável nova, maior, e não direto para precos: a seção 4 explica por quê.
if (maior == NULL) { … }
O realloc devolve NULL quando não há memória. Nesse caso o bloco antigo continua intacto em precos, e o programa ainda pode liberá-lo antes de sair.
precos = maior; capacidade = nova;
Deu certo: agora o caderno é o novo bloco, e a capacidade é a nova.
precos[tamanho] = novos[i]; tamanho++;
Guarda o item na primeira posição livre (a posição tamanho) e conta mais um. Depois de crescer, sempre existe essa posição livre.
free(precos);
Um único free no fim: o realloc já liberou cada bloco antigo quando trocou de caderno.

2. Dobrar a capacidade

O truque usado em praticamente toda biblioteca é: quando lotar, dobre a capacidade. Começando com 4 lugares, o caderno vai para 8, depois 16, 32, 64… Cada troca dá espaço para muitos itens novos. Só uma linha muda:

            size_t nova = (capacidade == 0) ? 4 : capacidade * 2;

O operador ternário diz: "se a capacidade é zero (a lista ainda não existe), comece com 4; senão, dobre". Sem esse cuidado, 0 * 2 daria zero, e a lista nunca cresceria. Com dez preços:

A diferença com mil itens

Este programa guarda os números de 0 a 999 em duas listas, uma crescendo de um em um e outra dobrando, e conta quantas vezes cada uma chamou o realloc:

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *a = NULL, *b = NULL;
    size_t cap_a = 0, cap_b = 0;
    int vezes_a = 0, vezes_b = 0;

    for (size_t n = 0; n < 1000; n++) {
        if (n == cap_a) {                    /* estratégia 1: +1 */
            cap_a = cap_a + 1;
            int *novo = realloc(a, cap_a * sizeof(int));
            if (novo == NULL) { free(a); free(b); return 1; }
            a = novo;
            vezes_a++;
        }
        a[n] = (int)n;

        if (n == cap_b) {                    /* estratégia 2: dobrar */
            cap_b = (cap_b == 0) ? 4 : cap_b * 2;
            int *novo = realloc(b, cap_b * sizeof(int));
            if (novo == NULL) { free(a); free(b); return 1; }
            b = novo;
            vezes_b++;
        }
        b[n] = (int)n;
    }

    printf("1000 itens com +1:     %d realocações (capacidade final %zu)\n", vezes_a, cap_a);
    printf("1000 itens dobrando:   %d realocações (capacidade final %zu)\n", vezes_b, cap_b);
    free(a);
    free(b);
    return 0;
}

$ gcc -std=c23 -Wall -Wextra conta.c -o conta
$ ./conta
1000 itens com +1:     1000 realocações (capacidade final 1000)
1000 itens dobrando:   9 realocações (capacidade final 1024)

Mil contra nove. E cada realocação pode copiar a lista inteira: crescendo de um em um, no pior caso o computador copia 0 + 1 + 2 + … + 999 = 499.500 números; dobrando, copia no máximo 4 + 8 + 16 + … + 512 = 1.020. Com um milhão de itens, a primeira estratégia vira uma eternidade; a segunda continua instantânea.

Missão: este programa guarda 10 preços crescendo de um em um e faz 10 realocações. Troque a linha da nova capacidade para começar com 4 e dobrar, e veja cair para Realocações: 3 e Capacidade final: 16.

#include <stdio.h>
#include <stdlib.h>

int main(void) {
    double *precos = NULL;
    size_t tamanho = 0;
    size_t capacidade = 0;
    int realocacoes = 0;

    for (int i = 1; i <= 10; i++) {
        if (tamanho == capacidade) {
            size_t nova = capacidade + 1;   /* troque esta linha */
            double *maior = realloc(precos, nova * sizeof(double));
            if (maior == NULL) {
                free(precos);
                return 1;
            }
            precos = maior;
            capacidade = nova;
            realocacoes++;
        }
        precos[tamanho] = i * 1.5;
        tamanho++;
    }

    printf("Itens: %zu\n", tamanho);
    printf("Realocações: %d\n", realocacoes);
    printf("Capacidade final: %zu\n", capacidade);
    free(precos);
    return 0;
}

3. Guardar tudo em funções: adicionar e liberar

Copiar aquele bloco do if em todo lugar que acrescenta um item seria pedir para errar. O certo é escrever a lógica uma vez, numa função. O problema: a função precisa mudar as três variáveis do main (o ponteiro, o tamanho e a capacidade). Como você viu em Passar por Ponteiro, para uma função mudar uma variável de fora, ela recebe o endereço da variável. E o endereço de um ponteiro é um ponteiro para ponteiro: double **.

De quebra, este programa lê os preços do teclado (ou de um arquivo) até a entrada acabar. É a situação em que o array que cresce brilha: ninguém sabe de antemão quantos preços vão chegar.

#include <stdio.h>
#include <stdlib.h>

bool adicionar(double **precos, size_t *tamanho, size_t *capacidade, double valor) {
    if (*tamanho == *capacidade) {
        size_t nova = (*capacidade == 0) ? 4 : *capacidade * 2;
        double *maior = realloc(*precos, nova * sizeof(double));
        if (maior == NULL) {
            return false;
        }
        *precos = maior;
        *capacidade = nova;
    }
    (*precos)[*tamanho] = valor;
    (*tamanho)++;
    return true;
}

void liberar(double **precos, size_t *tamanho, size_t *capacidade) {
    free(*precos);
    *precos = NULL;
    *tamanho = 0;
    *capacidade = 0;
}

int main(void) {
    double *precos = NULL;
    size_t tamanho = 0;
    size_t capacidade = 0;

    double preco;
    while (scanf("%lf", &preco) == 1) {
        if (!adicionar(&precos, &tamanho, &capacidade, preco)) {
            printf("Sem memória!\n");
            break;
        }
    }

    double total = 0.0;
    for (size_t i = 0; i < tamanho; i++) {
        total += precos[i];
    }
    printf("%zu itens (capacidade %zu)\n", tamanho, capacidade);
    printf("Total: R$ %.2f\n", total);

    liberar(&precos, &tamanho, &capacidade);
    return 0;
}
LinhaO que faz
bool adicionar(double **precos, size_t *tamanho, size_t *capacidade, double valor)Recebe o endereço das três variáveis da lista e o valor a guardar. Devolve true se deu certo e false se faltou memória. No C23, bool, true e false são palavras da linguagem; antes, era preciso #include <stdbool.h> (veja Booleanos).
*tamanho == *capacidadeO * segue o endereço até a variável do main: compara o tamanho e a capacidade de verdade.
realloc(*precos, …)*precos é o ponteiro precos do main (o caderno atual).
return false;Sem memória: a função desiste sem estragar nada. A lista antiga continua inteira e utilizável.
*precos = maior;Muda o ponteiro do main para o bloco novo.
(*precos)[*tamanho] = valor;Primeiro (*precos) pega o ponteiro do main; depois [*tamanho] escolhe a primeira posição livre. Os parênteses são obrigatórios (veja "Quando dá errado").
(*tamanho)++;Soma 1 ao tamanho do main. Também precisa dos parênteses: *tamanho++ andaria com o ponteiro em vez de somar no número (veja Precedência).
liberar(…)Devolve a memória e deixa a lista "zerada": ponteiro NULL, tamanho e capacidade 0. Assim, se alguém chamar adicionar de novo depois, a lista recomeça do zero em vez de usar memória já liberada.
while (scanf("%lf", &preco) == 1)Lê um número por vez enquanto a leitura der certo. Quando a entrada acaba (fim do arquivo, ou Ctrl+D no teclado) ou chega algo que não é número, o scanf devolve outra coisa e o laço termina (veja Entrada com scanf).

Vai ficar mais bonito com struct

Três variáveis soltas que sempre andam juntas, e funções com três parâmetros cheios de *: dá para sentir que falta alguma coisa. Falta a struct, que vem logo depois desta parte do guia. Com ela, o ponteiro, o tamanho e a capacidade viram uma coisa só, e a chamada fica adicionar(&lista, 12.50). Você vai reescrever esta lista assim em Structs e Ponteiros. A lógica (dobrar, conferir o realloc, liberar no fim) continua exatamente a mesma.

4. O jeito seguro de chamar realloc

Muita gente escreve assim, numa linha só:

precos = realloc(precos, nova * sizeof(double));   /* NÃO faça assim */

Funciona enquanto há memória. Mas quando o realloc falha, ele devolve NULL e não libera o bloco antigo (isso é de propósito, para você não perder os dados). Só que a linha acima guarda esse NULL em precos, por cima do único endereço que existia do bloco antigo. A lista continua lá na memória, mas ninguém mais sabe onde: não dá para usar nem para liberar.

Para ver acontecer, este programa pede, de propósito, espaço para um trilhão de preços (8 terabytes). O número vem da linha de comando (argv) só para o gcc não perceber o absurdo na hora de compilar:

#include <stdio.h>
#include <stdlib.h>

int main(int argc, char *argv[]) {
    size_t capacidade = 4;
    double *precos = malloc(capacidade * sizeof(double));
    if (precos == NULL) {
        return 1;
    }
    precos[0] = 12.50;

    /* um pedido grande demais, de propósito, para o realloc falhar */
    capacidade = (argc > 1) ? strtoull(argv[1], NULL, 10) : 8;

    precos = realloc(precos, capacidade * sizeof(double));
    if (precos == NULL) {
        printf("O realloc falhou. E a lista antiga?\n");
        return 1;
    }
    printf("Primeiro item: R$ %.2f\n", precos[0]);
    free(precos);
    return 0;
}

Os 32 bytes (4 preços de 8 bytes) do malloc da linha 6 ficaram perdidos: o NULL apagou o endereço deles. A forma segura usa uma variável a mais, como todos os exemplos desta aula:

double *maior = realloc(precos, nova * sizeof(double));
if (maior == NULL) {
    /* precos ainda aponta para a lista antiga, inteira:
       dá para avisar, salvar, liberar ou continuar sem o item novo */
    free(precos);
    return 1;
}
precos = maior;          /* só troca quando deu certo */
capacidade = nova;
Depois do realloc, o endereço antigo morreu

Quando o realloc muda o bloco de lugar, o bloco antigo é liberado. Qualquer ponteiro que você guardou para dentro dele (por exemplo, double *primeiro = &precos[0];) passa a apontar para memória que não é mais sua. Depois de crescer, use sempre precos, e pegue endereços de dentro da lista de novo, se precisar. O cenário completo está em "Quando dá errado".

Formas de crescer: qual usar

EstratégiaNova capacidadeVantagemDesvantagem
De um em umcapacidade + 1Nunca sobra lugar vazio.Um realloc por item: lento com muitos itens.
De tantos em tantoscapacidade + 100Simples; bom quando você sabe mais ou menos o tamanho.Com muitos itens, volta a ficar lento (10 mil itens = 100 trocas).
Dobrarcapacidade * 2 (começando em 4, 8 ou 16)Pouquíssimas trocas, sempre. É a escolha padrão.Pode sobrar até metade da capacidade vazia.
Multiplicar por 1,5capacidade + capacidade / 2Desperdiça menos que dobrar; usado por algumas bibliotecas.Um pouco mais de trocas. Cuidado: começando em 1, 1 + 1/2 é 1 e a lista nunca cresce.

Qual usar: dobre. Se você já sabe quantos itens vêm (por exemplo, leu a quantidade antes), reserve tudo de uma vez com malloc e nem precisa crescer. E se a lista nunca passa de um tamanho pequeno e conhecido, um array comum (double precos[50];) continua sendo o mais simples.

Encolher no fim (opcional)

Se a lista terminou com 10 itens numa capacidade de 16 e vai ficar muito tempo na memória, dá para devolver a sobra com realloc(precos, tamanho * sizeof(double)), também com a variável auxiliar. Para listas pequenas, não vale o trabalho. Cuidado com tamanho igual a 0: realloc com tamanho zero tem comportamento que muda de biblioteca para biblioteca (no C23 passou a ser comportamento indefinido); nesse caso, use free.

Quando dá errado

Esqueceu o sizeof: "heap-buffer-overflow" 
        double *maior = realloc(*precos, nova);   /* faltou * sizeof(double) */

O realloc conta em bytes. Sem o sizeof, a "capacidade 4" vira 4 bytes, metade de um único double. O gcc não avisa nada, e o programa escreve fora do bloco desde o primeiro item. O sanitizer de endereços (-fsanitize=address, veja Sanitizers) pega na hora:

$ gcc -std=c23 -Wall -Wextra -g -fsanitize=address semsizeof.c -o semsizeof
$ ./semsizeof < compras.txt

O que significa: o gcc avisou: pointer ‘primeiro’ may be used after ‘realloc’ = "o ponteiro primeiro pode ser usado depois do realloc". O programa ainda mostrou o valor certo, por sorte. O valgrind confirma o problema: Invalid read ("leitura inválida") de um endereço dentro de um bloco de 32 bytes free'd ("liberado") pelo realloc da linha 15.

Como resolver: depois que a lista pode ter crescido, pegue o endereço de novo (&precos[0]) ou, melhor, guarde a posição (o índice 0) em vez do endereço. Índices continuam valendo depois do realloc; endereços, não.

Sem os parênteses em (*precos)[*tamanho]: "Falha de segmentação" 
    *precos[*tamanho] = valor;        /* deveria ser (*precos)[*tamanho] */

$ gcc -std=c23 -Wall -Wextra -g parenteses.c -o parenteses
$ ./parenteses < compras.txt
Falha de segmentação     (imagem do núcleo gravada) ./parenteses < compras.txt

O que aconteceu: compilou sem nenhum aviso e morreu. O [] é mais forte que o *, então *precos[*tamanho] quer dizer *(precos[*tamanho]): trata precos (o endereço da variável do main) como se fosse um array de ponteiros e pega o "ponteiro" da posição tamanho. Na posição 0 dá certo por coincidência; na posição 1 já é lixo, e escrever lá derruba o programa. No editor do guia acontece o mesmo: Falha de segmentação (imagem do núcleo gravada).

Como resolver: (*precos)[*tamanho] = valor;. Primeiro siga o endereço até o ponteiro do main, depois escolha a posição. (Com uma struct, como você verá em Structs e Ponteiros, isso vira lista->dados[lista->tamanho], bem mais legível.)

A lista nunca cresce: capacidade * 2 começando em zero

O que aconteceu: com size_t nova = capacidade * 2; e a capacidade começando em 0, a nova capacidade é 0 * 2 = 0. O realloc recebe tamanho zero e o programa escreve num bloco que não tem lugar para nada.

Como resolver: trate o começo à parte: (capacidade == 0) ? 4 : capacidade * 2.

"definitely lost" no valgrind

O que aconteceu: faltou o free (ou o liberar) no fim, ou você usou precos = realloc(precos, …) e o realloc falhou.

Como resolver: todo array dinâmico termina com um free do ponteiro atual; e o realloc sempre vai para uma variável auxiliar.

Resumo

  • Um array que cresce precisa de três coisas: o ponteiro para a memória, o tamanho (itens guardados) e a capacidade (itens que cabem).
  • Quando tamanho == capacidade, cresça com realloc, sempre em bytes: nova * sizeof(double).
  • Dobre a capacidade (começando em 4, por exemplo): 1000 itens custam 9 realocações em vez de 1000.
  • Guarde o resultado do realloc numa variável auxiliar e confira o NULL antes de trocar o ponteiro.
  • Depois do realloc, endereços antigos de dentro da lista morrem; índices continuam valendo.
  • Coloque a lógica em funções (adicionar, liberar) e termine sempre com free. Confira com valgrind --leak-check=full.
  • Com structs, as três variáveis viram uma só, e o código fica bem mais limpo.
