Projeto Estoque da Lojinha

A Ana tem uma lojinha de papelaria e anota o estoque num caderno: quantos cadernos, canetas e borrachas ainda tem, e quanto custa cada um. Neste projeto ela troca o caderno por um programa em C que lembra de tudo de um dia para o outro. O segredo é um arquivo binário: o programa copia as fichas dos produtos da memória para o disco com fwrite e, na próxima vez, copia de volta com fread.

Você vai praticar
  • Desenhar uma struct que pode ir para o disco: com int32_t e o preço em centavos.
  • Gravar um array de structs com fwrite e ler de volta com fread (Arquivos Binários), conferindo o que eles devolvem.
  • Olhar os bytes do arquivo com xxd e achar cada campo.
  • Fazer um menu que lê linhas com fgets e converte números com strtol e strtod.
  • Arredondar dinheiro sem perder um centavo.
  • Pôr um cabeçalho no arquivo (assinatura e versão) e salvar com segurança, num arquivo temporário trocado com rename.

Versão 1 · A ficha do produto e o primeiro arquivo

Pense numa caixa de fichas de papelão, todas do mesmo tamanho: cada produto tem a sua, com os mesmos campos no mesmo lugar. Em C, a ficha é uma struct e a caixa é um array. Gravar o estoque é copiar a caixa inteira para o disco; ler é copiar de volta.

Antes do código, duas decisões sobre a ficha, porque ela vai parar no disco:

  • Os números são int32_t, e não int ou long. O int32_t tem 4 bytes em qualquer computador (aula Inteiros de Tamanho Fixo). Assim, a ficha tem sempre o mesmo tamanho, e o arquivo gravado hoje continua legível amanhã, mesmo com outro compilador.
  • O preço é guardado em centavos: R$ 15,90 vira o inteiro 1590. Um double não guarda 15,90 exato (aula float e double), e somar preços com vírgula vai acumulando erros. Com centavos inteiros, a conta é exata.

A primeira versão ainda não tem menu. Ela carrega o arquivo; se ele não existe, começa com três produtos. Depois mostra o estoque, "vende" um caderno e salva. Cada vez que roda, o caderno diminui: é o jeito mais simples de ver que o programa lembra.

#include <stdio.h>
#include <stdint.h>

#define ARQUIVO "estoque.bin"
#define MAX_PRODUTOS 100

typedef struct {
    int32_t codigo;
    char nome[24];
    int32_t quantidade;
    int32_t preco;          // em centavos: 1590 = R$ 15,90
} Produto;

// Lê o estoque do disco e devolve quantos produtos leu.
// Se o arquivo ainda não existe, devolve 0.
int carregar(Produto v[], int max) {
    FILE *f = fopen(ARQUIVO, "rb");
    if (f == NULL) {
        return 0;
    }
    size_t lidos = fread(v, sizeof(Produto), (size_t)max, f);
    fclose(f);
    return (int)lidos;
}

// Grava os n produtos no disco. Devolve true se gravou todos.
bool salvar(const Produto v[], int n) {
    FILE *f = fopen(ARQUIVO, "wb");
    if (f == NULL) {
        perror(ARQUIVO);
        return false;
    }
    size_t gravados = fwrite(v, sizeof(Produto), (size_t)n, f);
    fclose(f);
    return gravados == (size_t)n;
}

int main(void) {
    Produto estoque[MAX_PRODUTOS];
    int n = carregar(estoque, MAX_PRODUTOS);

    if (n == 0) {
        printf("Arquivo novo: começando com 3 produtos.\n");
        estoque[0] = (Produto){1, "Caderno", 12, 1590};
        estoque[1] = (Produto){2, "Caneta", 40, 250};
        estoque[2] = (Produto){3, "Borracha", 25, 175};
        n = 3;
    } else {
        printf("Li %d produtos de %s.\n", n, ARQUIVO);
    }

    for (int i = 0; i < n; i++) {
        printf("%d  %-10s %3d  R$ %d,%02d\n", estoque[i].codigo, estoque[i].nome,
               estoque[i].quantidade, estoque[i].preco / 100, estoque[i].preco % 100);
    }

    estoque[0].quantidade--;        // a Ana vendeu um caderno
    printf("Vendi 1 %s. Agora são %d.\n", estoque[0].nome, estoque[0].quantidade);

    if (!salvar(estoque, n)) {
        printf("Erro: o estoque não foi salvo!\n");
        return 1;
    }
    printf("Salvei %d produtos (%zu bytes).\n", n, n * sizeof(Produto));
    return 0;
}

Por que int32_t: o editor e o gcc não concordam sobre o long

A primeira ideia da Ana era usar os tipos de sempre: long no código e double no preço. Este programa compara o tamanho das duas fichas:

#include <stdio.h>
#include <stdint.h>

typedef struct {            // a ficha com os tipos de sempre
    long codigo;
    char nome[24];
    int quantidade;
    double preco;
} ProdutoVelho;

typedef struct {            // a ficha do projeto
    int32_t codigo;
    char nome[24];
    int32_t quantidade;
    int32_t preco;
} Produto;

int main(void) {
    printf("long: %zu bytes, double: %zu bytes\n", sizeof(long), sizeof(double));
    printf("ProdutoVelho: %zu bytes\n", sizeof(ProdutoVelho));
    printf("Produto:      %zu bytes\n", sizeof(Produto));
    return 0;
}

$ gcc -std=c23 -Wall -Wextra tamanhos.c -o tamanhos
$ ./tamanhos
long: 8 bytes, double: 8 bytes
ProdutoVelho: 48 bytes
Produto:      36 bytes

No editor do guia, o mesmo programa mostra outra coisa:

$ clang -std=c23 -Wall -Wextra tamanhos.c -o tamanhos
$ ./tamanhos
long: 4 bytes, double: 8 bytes
ProdutoVelho: 40 bytes
Produto:      36 bytes

O editor é um computador de 32 bits (WebAssembly), em que o long tem 4 bytes; no Linux de 64 bits do laboratório, 8. A ProdutoVelho tem 48 bytes num e 40 no outro (e ainda há bytes de enchimento entre os campos, para alinhar o double; veja Structs). Um arquivo gravado com ela num lado seria lido torto no outro. A Produto, só com int32_t e char, tem 36 bytes nos dois, sem enchimento.

O que aconteceu: o "w" quer dizer "vou escrever um arquivo novo". O fopen com "wb" apaga o conteúdo na mesma hora, antes de qualquer leitura. Depois, o fread num arquivo aberto só para escrita não lê nada e devolve 0, e o programa achou que era a primeira vez. O estoque de verdade foi perdido sem nenhuma mensagem de erro.

Como consertar: para ler, "rb"; para gravar tudo de novo, "wb". Quando estiver em dúvida, consulte a tabela de modos em Arquivos (fopen e fclose), e guarde uma cópia do arquivo (cp estoque.bin backup.bin) antes de testar um programa novo.

Versão 2 · O menu e o cadastro

Vender um caderno a cada execução foi só um teste. Agora o programa vira uma ferramenta: carrega o arquivo, mostra um menu e repete até a Ana escolher 0; aí salva. Os produtos de exemplo saem, e entra o cadastro. Como a Ana vai digitar nomes, quantidades e preços, toda leitura é feita com fgets, uma linha inteira por vez, e depois convertida e conferida, como na Calculadora.

// Mostra a pergunta e lê uma linha, sem o Enter do fim.
// Devolve false se a entrada acabou (Ctrl+D).
bool ler_linha(const char *pergunta, char *linha, int tamanho) {
    printf("%s", pergunta);
    if (fgets(linha, tamanho, stdin) == NULL) {
        return false;
    }
    linha[strcspn(linha, "\n")] = '\0';
    return true;
}

// Lê um número inteiro de 0 a 999999. Devolve -1 se não for válido.
int32_t ler_inteiro(const char *pergunta) {
    char linha[100];
    if (!ler_linha(pergunta, linha, sizeof linha)) {
        return -1;
    }
    char *fim = NULL;
    long valor = strtol(linha, &fim, 10);
    if (fim == linha || *fim != '\0' || valor < 0 || valor > 999999) {
        printf("\"%s\" não é um número válido.\n", linha);
        return -1;
    }
    return (int32_t)valor;
}

// Lê um preço em reais ("15.90" ou "15,90") e devolve em centavos.
// Devolve -1 se não for válido.
int32_t ler_preco(const char *pergunta) {
    char linha[100];
    if (!ler_linha(pergunta, linha, sizeof linha)) {
        return -1;
    }
    char *virgula = strchr(linha, ',');
    if (virgula != NULL) {
        *virgula = '.';             // aceita o jeito brasileiro
    }
    char *fim = NULL;
    double reais = strtod(linha, &fim);
    if (fim == linha || *fim != '\0' || reais < 0 || reais > 99999) {
        printf("\"%s\" não é um preço válido.\n", linha);
        return -1;
    }
    return (int32_t)(reais * 100 + 0.5);  // arredonda para o centavo
}

Por que conferir o tamanho do nome antes do strcpy

O strcpy copia até achar o '\0', sem saber o tamanho do destino. Com o nome de 32 letras acima, ele escreveria 33 bytes nos 24 de p.nome e estragaria os campos seguintes (aula Segurança). O que aconteceu: o double guarda os números em binário, e 4,35 não tem representação exata: o mais perto que ele consegue é um pouquinho menos, e 4.35 * 100 dá 434.99999999999994. A conversão (int32_t) não arredonda: ela corta a parte depois do ponto, e sobram 434 centavos. Com 0.29, o mesmo: 28.999999999999996 vira 28. O erro acontece só com alguns preços (15.90 e 2.50 deram certo), e por isso é traiçoeiro.

Como consertar: some meio centavo antes de cortar: (int32_t)(reais * 100 + 0.5). 434,99… + 0,5 = 435,49…, cortado dá 435. (Funciona para números positivos, que é o caso de preços. Outra saída é lround, do <math.h>, que no gcc pede -lm; veja Matemática.) É exatamente por isso que o programa guarda centavos: o double aparece uma única vez, na leitura, e é arredondado ali.

Um estoque muda o dia todo: chega mercadoria (entrada) e sai mercadoria (venda). A versão 3 acrescenta quatro opções ao menu:

O programa funciona, mas confia demais no arquivo. Ele lê qualquer estoque.bin que encontrar, de 36 em 36 bytes, sem saber se aquilo é mesmo um estoque. E, se um dia a ficha mudar (um campo novo, por exemplo), os arquivos antigos vão ser lidos tortos, sem nenhum aviso (o cenário "os dois programas não concordam sobre a struct", em Arquivos Binários). A versão 4 resolve isso de dois jeitos.

1. Um cabeçalho com assinatura e versão

Muitos formatos de arquivo começam com alguns bytes fixos, a assinatura (ou "número mágico"): todo PDF começa com %PDF, todo PNG com \x89PNG. O comando file do Linux reconhece o tipo de um arquivo por esses bytes, sem olhar o nome. O estoque da Ana vai começar com 12 bytes de cabeçalho:

BytesCampoConteúdo
0 a 3assinaturaAs letras L O J A: "isto é um estoque da lojinha".
4 a 7versao1. Se o formato mudar, a versão nova grava 2, e cada programa sabe o que está lendo.
8 a 11totalQuantos produtos vêm depois. Assim dá para saber se o arquivo foi cortado.
12 em dianteos produtosAs fichas de 36 bytes, como antes. O produto i começa no byte 12 + i × 36.

2. Salvar num arquivo temporário e trocar no fim

O salvar das versões anteriores abre estoque.bin com "wb", e nesse instante o estoque antigo já foi apagado. Se o programa morrer no meio da gravação (falta de luz, disco cheio, um Ctrl+C), a Ana fica sem o novo e sem o antigo. O jeito seguro, usado por editores de texto e bancos de dados:

  1. grave tudo num arquivo novo, estoque.tmp;
  2. confira cada fwrite e o fclose;
  3. só então troque o nome com rename("estoque.tmp", "estoque.bin"). No Linux, o rename substitui o arquivo antigo de uma vez só: quem abrir estoque.bin vê o antigo inteiro ou o novo inteiro, nunca um pedaço.

void cadastrar(Produto v[], int *n) {
    if (*n == MAX_PRODUTOS) {
        printf("O estoque está cheio (%d produtos).\n", MAX_PRODUTOS);
        return;
    }
    Produto p = {0};
    char linha[100];
    if (!ler_linha("Nome: ", linha, sizeof linha) || linha[0] == '\0') {
        printf("Cadastro cancelado.\n");
        return;
    }
    if (strlen(linha) >= sizeof p.nome) {
        printf("Nome comprido demais (no máximo %zu letras).\n", sizeof p.nome - 1);
        return;
    }
    strcpy(p.nome, linha);
    p.quantidade = ler_inteiro("Quantidade: ");
    if (p.quantidade < 0) {
        return;
    }
    p.preco = ler_preco("Preço (R$): ");
    if (p.preco < 0) {
        return;
    }
    p.codigo = 1;                   // o próximo código livre

        if (v[i].codigo >= p.codigo) {
            p.codigo = v[i].codigo + 1;
        }
    }

    (*n)++;

}

// Lê o estoque do disco. Devolve quantos produtos leu (0 se o arquivo
// ainda não existe) ou -1 se o arquivo não é um estoque da lojinha.
int carregar(Produto v[], int max) {
    FILE *f = fopen(ARQUIVO, "rb");
    if (f == NULL) {
        return 0;
    }
    Cabecalho cab;
    if (fread(&cab, sizeof cab, 1, f) != 1 ||
        memcmp(cab.assinatura, "LOJA", 4) != 0) {
        printf("%s não é um arquivo da lojinha.\n", ARQUIVO);
        fclose(f);
        return -1;
    }
    if (cab.versao != VERSAO_ARQUIVO) {
        printf("%s é da versão %d; eu só leio a versão %d.\n",
               ARQUIVO, cab.versao, VERSAO_ARQUIVO);
        fclose(f);
        return -1;
    }
    if (cab.total < 0 || cab.total > max) {
        printf("%s diz ter %d produtos; eu aceito até %d.\n",
               ARQUIVO, cab.total, max);
        fclose(f);
        return -1;
    }
    size_t lidos = fread(v, sizeof(Produto), (size_t)cab.total, f);
    fclose(f);
    if (lidos != (size_t)cab.total) {
        printf("%s está cortado: li %zu de %d produtos.\n",
               ARQUIVO, lidos, cab.total);
        return -1;
    }
    return cab.total;
}

// Grava num arquivo temporário e só no fim troca pelo verdadeiro.
// Devolve true se deu tudo certo.
bool salvar(const Produto v[], int n) {
    FILE *f = fopen(TEMPORARIO, "wb");
    if (f == NULL) {
        perror(TEMPORARIO);
        return false;
    }
    Cabecalho cab = {{'L', 'O', 'J', 'A'}, VERSAO_ARQUIVO, n};
    bool ok = fwrite(&cab, sizeof cab, 1, f) == 1 &&
              fwrite(v, sizeof(Produto), (size_t)n, f) == (size_t)n;
    if (fclose(f) != 0) {
        ok = false;
    }
    if (!ok || rename(TEMPORARIO, ARQUIVO) != 0) {
        perror("Erro ao salvar");
        remove(TEMPORARIO);
        return false;
    }
    return true;
}

Resumo

  • Uma struct de tamanho fixo vira um registro no arquivo: fwrite(v, sizeof(Produto), n, f) grava o array inteiro e fread lê de volta.
  • Para o disco, use int32_t e companhia: o long tem 8 bytes no gcc e 4 no editor, e a ficha mudaria de tamanho.
  • Dinheiro em centavos inteiros. Ao converter de double, arredonde com + 0.5: o (int32_t) corta, e 4,35 viraria 4,34.
  • "rb" para ler, "wb" para regravar tudo; o "wb" apaga o arquivo na hora.
  • Confira o que fread, fwrite e fclose devolvem, e nunca confie num número que veio do arquivo.
  • Um cabeçalho com assinatura e versão faz o programa recusar arquivos estranhos, cortados ou de outro formato.
  • Salvar com segurança: grave num temporário, confira tudo e troque com rename.
