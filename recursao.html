C Recursão

Na aula Funções você viu que uma função pode chamar outra. Ela também pode chamar a si mesma. Isso se chama recursão. Parece um truque de mágica (como uma função que ainda não terminou pode usar a si própria?), mas é só uma forma de resolver um problema grande com a versão menor do mesmo problema. Nesta aula você vai escrever suas primeiras funções recursivas, ver a "pilha de chamadas" crescer e encolher, descobrir quando a recursão fica lenta demais e ver o programa morrer quando ela não tem fim.

Você vai aprender
  • O que é uma função recursiva e as duas partes que ela sempre tem: o caso base e o passo recursivo.
  • Em que ordem as linhas rodam: o que vem antes da chamada roda na "ida", o que vem depois roda na "volta".
  • Como uma função recursiva devolve um valor (o fatorial) e como acompanhar a pilha de chamadas.
  • Por que o Fibonacci recursivo fica lento, contando as chamadas.
  • O que acontece sem caso base: o aviso infinite recursion detected e a Falha de segmentação.
  • Quando usar recursão e quando um laço é melhor.

Todos os programas foram compilados com o gcc 15.2 na máquina fictícia da Ana (usuária ana, computador notebook), na pasta ~/c, com o comando padrão do guia: gcc -std=c23 -Wall -Wextra arquivo.c -o programa. Você pode repetir cada um no editor do guia.

A ideia: as bonecas russas

A Ana ganhou uma matriosca, aquela boneca russa que tem uma boneca menor dentro, que tem outra menor dentro, e assim por diante. Para chegar à bonequinha do centro, ela segue uma única regra:

  • Se a boneca é a menorzinha (não abre mais), achei! Parei.
  • Senão, abro a boneca e faço a mesma coisa com a boneca de dentro.

Repare que a regra usa a si mesma ("faço a mesma coisa"), mas sempre com uma boneca menor. Por isso ela termina: uma hora chega a boneca que não abre. Toda função recursiva tem essas duas partes:

ParteNas bonecasNa função
Caso baseA boneca menorzinha: não abre, a busca paraUm if que responde sem chamar a função de novo
Passo recursivoAbrir e repetir com a boneca de dentroA função chama a si mesma com um problema menor (por exemplo, n - 1)

Esqueça o caso base, ou faça o problema não diminuir, e a função chama a si mesma para sempre (bom, quase: a seção 5 mostra como o programa morre).

1. A primeira função recursiva: contagem regressiva

A Ana quer uma contagem para a largada da corrida da escola: 3... 2... 1... Já!. Com um laço seria fácil (for). Com recursão, o raciocínio é: "contar a partir de 3 é mostrar 3 e depois contar a partir de 2".

#include <stdio.h>

void contagem(int n) {
    if (n == 0) {
        printf("Já!\n");
        return;
    }
    printf("%d...\n", n);
    contagem(n - 1);
}

int main(void) {
    contagem(3);
    return 0;
}
void contagem(int n)
Uma função comum, que recebe um número (Parâmetros) e não devolve nada.
if (n == 0) { printf("Já!\n"); return; }
O caso base: quando a contagem chega a zero, a função mostra Já! e não chama mais ninguém. O return; sai da função na hora (Valor de Retorno).
printf("%d...\n", n);
Mostra o número atual.
contagem(n - 1);
O passo recursivo: a função chama a si mesma com um número menor. Cada chamada chega mais perto do zero.
$ gcc -std=c23 -Wall -Wextra contagem.c -o contagem
$ ./contagem
3...
2...
1...
Já!

O que aconteceu, chamada por chamada:

  1. O main chama contagem(3). Como 3 não é 0, ela mostra 3... e chama contagem(2).
  2. contagem(2) mostra 2... e chama contagem(1).
  3. contagem(1) mostra 1... e chama contagem(0).
  4. contagem(0) cai no caso base: mostra Já! e retorna.
  5. Então contagem(1) termina (não há mais nada depois da chamada), depois contagem(2), depois contagem(3), e o programa volta ao main.

Um detalhe importante: contagem(3), contagem(2), contagem(1) e contagem(0) são quatro chamadas diferentes, e cada uma tem o seu próprio n. É como na aula Escopo: a variável local nasce a cada chamada. O n que vale 3 continua lá, esperando, enquanto as chamadas de dentro rodam com os seus n.

A ida e a volta

Uma chamada recursiva divide a função em duas partes: o que vem antes dela roda na ida (abrindo as bonecas); o que vem depois só roda na volta, quando a chamada de dentro termina (fechando as bonecas). Veja com dois printf, um de cada lado:

#include <stdio.h>

void boneca(int n) {
    printf("abrindo a boneca %d\n", n);
    if (n > 1) {
        boneca(n - 1);
    }
    printf("fechando a boneca %d\n", n);
}

int main(void) {
    boneca(3);
    return 0;
}

$ gcc -std=c23 -Wall -Wextra idavolta.c -o idavolta
$ ./idavolta
abrindo a boneca 3
abrindo a boneca 2
abrindo a boneca 1
fechando a boneca 1      « a boneca 1 é o caso base: não abre outra
fechando a boneca 2
fechando a boneca 3

Aqui o caso base está escrito "ao contrário": em vez de if (n == 1) return;, a função só chama a si mesma se n > 1. As duas formas são comuns. O que importa é que existe um valor de n em que a função não chama mais ninguém.

Repare na ordem da volta: 1, 2, 3. A última boneca aberta é a primeira a ser fechada. As chamadas se empilham como pratos: o último prato colocado na pilha é o primeiro a sair.

Experimente: rode o programa. Depois troque boneca(3) por boneca(5). Por último, apague o printf de "fechando" e veja que só sobra a ida; volte com ele e apague o de "abrindo".

2. Devolver um valor: o fatorial

O fatorial de um número, escrito n!, é a multiplicação de todos os inteiros de 1 até ele: 4! = 4 × 3 × 2 × 1 = 24. Ele responde, por exemplo, de quantas formas diferentes 4 pessoas podem formar uma fila. Repare que dentro de 4! está escondido o 3!:

  • 4! = 4 × (3 × 2 × 1) = 4 × 3!
  • e, em geral, n! = n × (n - 1)!;
  • com o caso base 1! = 1 (e, por convenção da matemática, 0! = 1).

Essa definição vira código quase palavra por palavra:

#include <stdio.h>

int fatorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * fatorial(n - 1);
}

int main(void) {
    for (int i = 0; i <= 5; i++) {
        printf("%d! = %d\n", i, fatorial(i));
    }
    return 0;
}
int fatorial(int n)
Agora a função devolve um int: o resultado da conta.
if (n <= 1) { return 1; }
O caso base: 0! e 1! valem 1. O <= (em vez de ==) cobre os dois de uma vez.
return n * fatorial(n - 1);
O passo recursivo. Para devolver o resultado, a função primeiro precisa saber quanto vale fatorial(n - 1): ela chama a si mesma, espera a resposta, multiplica por n e só então devolve.
$ gcc -std=c23 -Wall -Wextra fatorial.c -o fatorial
$ ./fatorial
0! = 1
1! = 1
2! = 2
3! = 6
4! = 24
5! = 120

A pilha de chamadas, passo a passo

Como fatorial(4) chega a 24? Cada chamada fica "pendurada", esperando a resposta da chamada de dentro. O computador guarda as chamadas pendentes numa estrutura chamada pilha de chamadas (call stack): cada chamada ganha uma "bandeja" com as suas variáveis, empilhada em cima da anterior.

MomentoO que aconteceChamadas na pilha
1main chama fatorial(4), que precisa de fatorial(3)main, f(4)
2fatorial(3) precisa de fatorial(2)main, f(4), f(3)
3fatorial(2) precisa de fatorial(1)main, f(4), f(3), f(2)
4fatorial(1) é o caso base: devolve 1main, f(4), f(3), f(2), f(1)
5fatorial(2) calcula 2 * 1 e devolve 2main, f(4), f(3), f(2)
6fatorial(3) calcula 3 * 2 e devolve 6main, f(4), f(3)
7fatorial(4) calcula 4 * 6 e devolve 24 ao mainmain, f(4)

A pilha de chamadas é a mesma pilha de memória onde moram as variáveis locais. Ela tem um tamanho limitado (no Linux, 8 MB), o que vai importar na seção 5. A aula Pilha e Heap, no Nível 2, mostra essa memória em detalhes.

O fatorial cresce rápido

O fatorial cresce tão depressa que estoura o int logo no 13. Com long long (Inteiros) vai até o 20:

#include <stdio.h>

int fatorial(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * fatorial(n - 1);
}

long long fatorial_ll(int n) {
    if (n <= 1) {
        return 1;
    }
    return n * fatorial_ll(n - 1);
}

int main(void) {
    printf("12! com int:       %d\n", fatorial(12));
    printf("13! com int:       %d\n", fatorial(13));
    printf("13! com long long: %lld\n", fatorial_ll(13));
    printf("20! com long long: %lld\n", fatorial_ll(20));
    printf("21! com long long: %lld\n", fatorial_ll(21));
    return 0;
}

$ ./fatorial13

Nenhum aviso: o compilador não sabe com que números você vai chamar a função. O estouro de um inteiro com sinal é comportamento indefinido; aqui ele apareceu como um número errado. Isso não é culpa da recursão: um laço daria os mesmos números. É só um lembrete de escolher um tipo que caiba o resultado.

3. Usar a volta: um número em binário

Às vezes a recursão é a forma mais simples de resolver o problema. Para escrever um número em binário (a base 2, explicada em Operadores de Bits), o jeito clássico é dividir por 2 várias vezes e anotar os restos. O problema: os restos saem de trás para a frente. Para 6: 6 % 2 = 0, 3 % 2 = 1, 1 % 2 = 1, e o binário de 6 é 110, os restos lidos do último para o primeiro.

Com recursão, a inversão sai de graça. A função primeiro escreve o resto do número (chamando a si mesma com n / 2) e só na volta escreve o último dígito:

#include <stdio.h>

void binario(int n) {
    if (n >= 2) {
        binario(n / 2);
    }
    printf("%d", n % 2);
}

int main(void) {
    int numeros[] = {5, 6, 13, 255};
    for (int i = 0; i < 4; i++) {
        printf("%3d em binário: ", numeros[i]);
        binario(numeros[i]);
        printf("\n");
    }
    return 0;
}
if (n >= 2) { binario(n / 2); }
Se o número tem mais de um dígito em binário, escreva primeiro os dígitos da frente, que são o binário de n / 2. Quando n é 0 ou 1 (caso base), não há nada na frente.
printf("%d", n % 2);
Depois da chamada, na volta: escreve o último dígito, o resto da divisão por 2.
$ gcc -std=c23 -Wall -Wextra binario.c -o binario
$ ./binario
  5 em binário: 101
  6 em binário: 110
 13 em binário: 1101
255 em binário: 11111111

Para binario(6): a chamada com 6 chama a com 3, que chama a com 1. A com 1 escreve 1; na volta, a com 3 escreve 3 % 2 = 1; por último, a com 6 escreve 6 % 2 = 0. Resultado: 110. Troque a ordem (o printf antes do if) e os dígitos saem invertidos.

4. O custo escondido: Fibonacci

A sequência de Fibonacci começa com 0 e 1, e cada número seguinte é a soma dos dois anteriores: 0, 1, 1, 2, 3, 5, 8, 13, 21… A definição é recursiva, e o código parece perfeito:

#include <stdio.h>

long long chamadas = 0;

long long fib(int n) {
    chamadas++;
    if (n < 2) {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

int main(void) {
    int testes[] = {10, 20, 30, 40};
    for (int i = 0; i < 4; i++) {
        chamadas = 0;
        long long r = fib(testes[i]);
        printf("fib(%d) = %lld, com %lld chamadas\n", testes[i], r, chamadas);
    }
    return 0;
}
long long chamadas = 0;
Uma variável global (Escopo), só para medir: cada vez que fib roda, ela soma 1. Num programa de verdade evitaríamos a global; aqui ela serve de contador.
if (n < 2) { return n; }
Dois casos base de uma vez: fib(0) é 0 e fib(1) é 1.
return fib(n - 1) + fib(n - 2);
Aqui está a novidade: duas chamadas recursivas. Cada uma delas, por sua vez, faz mais duas…
$ gcc -std=c23 -Wall -Wextra fib.c -o fib
$ time ./fib

fib(20) = 6765, com 21891 chamadas
fib(30) = 832040, com 2692537 chamadas
fib(40) = 102334155, com 331160281 chamadas

Mais de 331 milhões de chamadas para calcular fib(40)! (O time antes do comando mede quanto tempo o programa levou: real é o tempo no relógio, cerca de 1 segundo.) O motivo é que a função recalcula as mesmas coisas muitas vezes. fib(5) chama fib(4) e fib(3); mas fib(4) também chama fib(3). O fib(3) é calculado duas vezes, o fib(2) três vezes, e assim por diante:

fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2)
│   │   │   ├── fib(1)
│   │   │   └── fib(0)
│   │   └── fib(1)
│   └── fib(2)
│       ├── fib(1)
│       └── fib(0)
└── fib(3)
    ├── fib(2)
    │   ├── fib(1)
    │   └── fib(0)
    └── fib(1)

Na saída acima, cada vez que n aumenta 10, o número de chamadas fica cerca de 123 vezes maior (331 160 281 ÷ 2 692 537 ≈ 123). O fib(50) levaria uns dois minutos; o fib(60), horas. Um laço que guarda só os dois últimos números faz a mesma conta num instante:

#include <stdio.h>

long long fib(int n) {
    long long anterior = 0;
    long long atual = 1;
    if (n == 0) {
        return 0;
    }
    for (int i = 2; i <= n; i++) {
        long long proximo = anterior + atual;
        anterior = atual;
        atual = proximo;
    }
    return atual;
}

int main(void) {
    printf("fib(40) = %lld\n", fib(40));
    printf("fib(90) = %lld\n", fib(90));
    return 0;
}

$ time ./fiblaco

O laço fez 39 voltas para o fib(40), contra 331 milhões de chamadas da versão recursiva. A lição não é "recursão é lenta", e sim: cuidado com a recursão que se divide em várias chamadas e repete trabalho. O fatorial e o binário fazem uma chamada só por vez e não têm esse problema.

5. Sem caso base: a pilha estoura

Cada chamada que ainda não terminou ocupa uma bandeja na pilha. Uma função que chama a si mesma sem parar empilha bandejas até a pilha (8 MB no Linux) acabar. Este programa desce os andares de um prédio sem fim e avisa a cada 50 000 andares:

#include <stdio.h>

void descer(int andar) {
    if (andar % 50000 == 0) {
        printf("andar %d\n", andar);
    }
    descer(andar + 1);
}

int main(void) {
    descer(1);
    return 0;
}

$ gcc -std=c23 -Wall -Wextra infinita.c -o infinita
infinita.c: In function ‘descer’:
infinita.c:3:6: warning: infinite recursion detected [-Winfinite-recursion]
    3 | void descer(int andar) {
      |      ^~~~~~
infinita.c:7:5: note: recursive call
    7 |     descer(andar + 1);
      |     ^~~~~~~~~~~~~~~~~
$ ./infinita
andar 50000
andar 100000
andar 150000
andar 200000
andar 250000
Falha de segmentação     (imagem do núcleo gravada) ./infinita
$ echo $?
139
warning: infinite recursion detected
"Recursão infinita detectada". O gcc percebeu que todo caminho pela função chama a função de novo: não há caso base. O if aqui só decide se mostra o andar; com ou sem printf, a chamada acontece.
note: recursive call
"Chamada recursiva": a linha que causa o problema.
andar 250000 … Falha de segmentação
Depois de mais de 250 mil chamadas empilhadas, a pilha acabou e o sistema matou o programa. É o estouro de pilha (stack overflow). O código 139 é o mesmo de qualquer falha de segmentação: a mensagem não diz que a culpa é da recursão.

No editor do guia, o Clang avisa com outras palavras: warning: all paths through this function will call itself [-Winfinite-recursion] ("todos os caminhos por esta função vão chamar a ela mesma"). O programa também morre com Falha de segmentação (imagem do núcleo gravada) e código 139, só que mais cedo, logo depois do andar 50000: no WebAssembly cada chamada ocupa mais espaço na pilha.

Pior que esquecer o caso base é ter um que a função pula. A Ana fez uma contagem de 2 em 2:

Recursão × laço: qual usar

Tudo o que uma recursão faz, um laço também consegue (às vezes com mais trabalho). O fatorial, por exemplo:

#include <stdio.h>

int fatorial(int n) {
    int resultado = 1;
    for (int i = 2; i <= n; i++) {
        resultado = resultado * i;
    }
    return resultado;
}

int main(void) {
    printf("5! = %d\n", fatorial(5));
    return 0;
}

$ gcc -std=c23 -Wall -Wextra fatlaco.c -o fatlaco
$ ./fatlaco
5! = 120
RecursãoLaço (for, while)
MemóriaUma bandeja na pilha por chamada; milhares de chamadas podem estourar a pilhaAs mesmas poucas variáveis do começo ao fim
VelocidadeCada chamada tem um pequeno custo; com várias chamadas por vez (Fibonacci), pode repetir trabalhoEm geral, mais rápido
ClarezaFica curta e parecida com a definição quando o problema é "o mesmo problema, menor"Mais clara para "repita N vezes" e "percorra a lista"
Bons exemplosEscrever em binário, MDC de Euclides, percorrer pastas dentro de pastas, árvores (estruturas ligadas), ordenar dividindo ao meioSomar uma lista, contar, ler linhas de um arquivo, Fibonacci

Regra prática: se o laço é simples, use o laço. Use recursão quando o problema se divide naturalmente em pedaços menores do mesmo tipo e a profundidade é pequena (dezenas ou milhares de chamadas, não milhões). Duas funções que chamam uma à outra também são recursão; a aula Protótipos mostra um exemplo (par e ímpar) e por que ele precisa de protótipo.

Quando dá errado

Falha de segmentação (código 139) numa função recursiva

O que significa: provavelmente a pilha estourou: a função chamou a si mesma vezes demais. Ou não tem caso base (o gcc avisa infinite recursion detected; o Clang, all paths through this function will call itself), ou o caso base é pulado (sem aviso), ou o problema é grande demais para recursão.

Como consertar: confira as três perguntas do quadro da seção 5. Para ver até onde a função chegou, ponha um printf("n = %d\n", n); no começo dela (com \n, para a linha aparecer antes de o programa morrer). Se a profundidade for mesmo enorme, troque por um laço.

warning: control reaches end of non-void function e value computed is not used 
#include <stdio.h>

int fatorial(int n) {
    if (n <= 1) {
        return 1;
    }
    n * fatorial(n - 1);
}

int main(void) {
    printf("5! = %d\n", fatorial(5));
    return 0;
}

$ gcc -std=c23 -Wall -Wextra semreturn.c -o semreturn
semreturn.c: In function ‘fatorial’:
semreturn.c:7:7: warning: value computed is not used [-Wunused-value]
    7 |     n * fatorial(n - 1);
      |     ~~^~~~~~~~~~~~~~~~~
semreturn.c:8:1: warning: control reaches end of non-void function [-Wreturn-type]
    8 | }
      | ^
$ ./semreturn
5! = 1

O que significa: faltou o return no passo recursivo. A conta n * fatorial(n - 1) é feita e jogada fora ("valor calculado não é usado"), e a função chega ao } sem devolver nada ("o controle chega ao fim de uma função não void"). O resultado é lixo: no gcc saiu 1; no editor, o Clang avisa expression result unused e non-void function does not return a value in all control paths, e o programa mostra 5! = 0.

Como consertar: return n * fatorial(n - 1);. Numa função recursiva que devolve valor, todo caminho tem de terminar num return.

O programa fica lento demais (e não dá erro)

O que significa: a função faz duas (ou mais) chamadas recursivas e recalcula os mesmos valores, como o Fibonacci. O número de chamadas cresce de forma explosiva.

Como consertar: reescreva com um laço que guarda os resultados anteriores (como o fiblaco.c). Se o programa travou no terminal, Ctrl+C o interrompe.

Resultado errado com números grandes, sem aviso

O que significa: o resultado não coube no tipo. 13! com int deu 1932053504, e 21! com long long deu um número negativo.

Como consertar: use um tipo maior (long long) e saiba o limite dele (o long long aguenta até 20!). Veja Inteiros.

Exercícios

1. O caso base

Complete o caso base de uma função que calcula 2 elevado a n (lembre: qualquer número elevado a 0 vale 1):

int potencia2(int n) { if (n == 0) { return ; } return 2 * potencia2(n - 1); }

2. O passo recursivo

Complete o passo recursivo da contagem regressiva, para que cada chamada fique mais perto do zero:

printf("%d...\n", n); contagem();

3. Código de saída

Uma recursão sem fim estourou a pilha e o programa morreu com Falha de segmentação. Que número o echo $? mostra?

4. Na função void f(int n) { if (n > 0) { f(n - 1); } printf("%d ", n); }, o que f(3) mostra?

5. Por que o fib(40) recursivo faz mais de 331 milhões de chamadas?

6. Uma contagem de 2 em 2 tem o caso base if (n == 0). O que acontece com contagem2(7)?

Missão final: a soma dos dígitos

Missão: escreva a função recursiva soma_digitos, que soma os algarismos de um número (2026 → 2 + 0 + 2 + 6 = 10). Use duas ideias da aula Operadores Aritméticos: n % 10 é o último algarismo (2026 % 10 = 6) e n / 10 é o número sem ele (2026 / 10 = 202). A regra:

  • caso base: se n < 10, o número tem um algarismo só, e a soma é o próprio n;
  • passo recursivo: senão, a soma é o último algarismo mais a soma dos algarismos de n / 10.

A saída tem de ser exatamente esta, sem avisos:

soma_digitos(7) = 7
soma_digitos(2026) = 10
soma_digitos(9999) = 36
#include <stdio.h>

int soma_digitos(int n) {
    // caso base: um algarismo só

    // passo recursivo: último algarismo + soma dos outros
    return 0;
}

int main(void) {
    printf("soma_digitos(7) = %d\n", soma_digitos(7));
    printf("soma_digitos(2026) = %d\n", soma_digitos(2026));
    printf("soma_digitos(9999) = %d\n", soma_digitos(9999));
    return 0;
}

#include <stdio.h>

int soma_digitos(int n) {
    if (n < 10) {
        return n;
    }
    return n % 10 + soma_digitos(n / 10);
}

int main(void) {
    printf("soma_digitos(7) = %d\n", soma_digitos(7));
    printf("soma_digitos(2026) = %d\n", soma_digitos(2026));
    printf("soma_digitos(9999) = %d\n", soma_digitos(9999));
    return 0;
}

Para soma_digitos(2026), a pilha fica com quatro chamadas: 2026, 202, 20 e 2. A última é o caso base e devolve 2; na volta, as somas vão se acumulando: 2 + 0 = 2, 2 + 2 = 4, 4 + 6 = 10.

Resumo

  • Uma função recursiva chama a si mesma. Ela sempre tem um caso base (responde sem chamar de novo) e um passo recursivo (chama com um problema menor).
  • Cada chamada tem as suas próprias variáveis locais. O código antes da chamada roda na ida; o código depois roda na volta, na ordem inversa.
  • As chamadas pendentes ficam na pilha de chamadas, que é limitada (8 MB no Linux). Recursão sem fim estoura a pilha: Falha de segmentação, código 139. O -Wall avisa quando não há caso base (infinite recursion detected), mas não quando o caso base é pulado.
  • Numa função que devolve valor, escreva return no passo recursivo: return n * fatorial(n - 1);.
  • Recursão com várias chamadas por vez (Fibonacci) pode repetir trabalho e ficar lentíssima; um laço resolve.
  • Se um laço simples resolve, prefira o laço. Use recursão quando o problema é "o mesmo problema, menor" e a profundidade é pequena.
