C Introdução

O C (lê-se "cê") é uma linguagem de programação pequena, criada em 1972, feita para escrever programas rápidos que falam quase diretamente com o computador. Ela é compilada: antes de rodar, o seu texto é traduzido para a língua do processador. Nesta aula você vai entender o que isso quer dizer, de onde o C veio, onde ele está hoje (muito provavelmente dentro do aparelho em que você lê esta página) e como ele se compara com o C++ e o Python.

  • O que é uma linguagem compilada e por que isso deixa o C rápido.
  • A história: Dennis Ritchie, o Bell Labs e o sistema Unix.

Primeiro: o que é programar?

Um computador não "entende" nada sozinho. Ele só sabe seguir instruções, uma de cada vez, muito rápido. Programar é escrever essas instruções. Uma linguagem de programação é o idioma combinado entre você e o computador: um conjunto de palavras e símbolos com regras rígidas (onde vai o ponto e vírgula, onde abrem e fecham as chaves).

Pense numa receita de bolo. Ela tem uma lista de passos, em ordem: "pré-aqueça o forno", "misture os ovos com o açúcar", "se a massa estiver grossa, acrescente leite". Um programa é igual: uma lista de passos, alguns com decisões ("se…") e repetições ("bata até ficar homogêneo"). A diferença é que o computador segue a receita ao pé da letra. Se você escrever pritnf em vez de printf, ele não adivinha o que você quis dizer: ele para e reclama. Essas reclamações são as mensagens de erro, e o guia vai ensinar você a lê-las.

A língua do processador

O processador (a CPU, o "cérebro" do computador) não entende português, nem inglês, nem C. Ele só entende código de máquina: números que querem dizer coisas como "some estes dois valores" ou "guarde isto na memória". Escrever programas diretamente em números seria um pesadelo. Por isso existem as linguagens de programação, que são feitas para pessoas lerem e escreverem.

Alguém precisa traduzir o texto da linguagem para os números do processador. Existem dois jeitos de fazer isso:

JeitoComo funcionaComparaçãoExemplos
CompilarUm programa chamado compilador traduz o texto inteiro antes, uma vez só, e gera um arquivo executável. Depois, o executável roda sozinho, quantas vezes você quiser.Traduzir um livro inteiro e imprimir a tradução. Quem lê a versão traduzida não precisa do tradutor.C, C++, Rust, Go
InterpretarUm programa chamado interpretador lê o texto e vai executando linha por linha, toda vez que o programa roda.Um intérprete numa palestra, traduzindo frase por frase enquanto a pessoa fala. Sem o intérprete na sala, ninguém entende.Python, JavaScript, PHP

O C é compilado. Essa é a principal razão de ele ser tão rápido: quando o programa roda, a tradução já foi feita, e o processador só executa. O compilador mais usado no Linux, e o que aparece nos terminais deste guia, é o gcc (GNU Compiler Collection, "coleção de compiladores do projeto GNU"). A aula Como o C Vira Programa mostra a tradução acontecendo, etapa por etapa.

O que é o C

O C é uma linguagem de uso geral (serve para quase qualquer tipo de programa), mas brilha num lugar específico: programas que precisam ser rápidos, pequenos e próximos da máquina. Três características explicam isso:

  • Rápido. O compilador gera código de máquina, e a linguagem não coloca nada "no meio do caminho": cada linha de C vira poucas instruções do processador.
  • Pequeno. A linguagem inteira cabe num livro fino. Ela tem pouco mais de 50 palavras reservadas (eram 32 no primeiro padrão) (int, if, while, return…) e uma biblioteca padrão enxuta. Dá para aprender o C inteiro, coisa rara entre as linguagens.
  • Perto da máquina. Em C você mexe diretamente na memória: sabe onde cada dado está guardado e quantos bytes ele ocupa. É por isso que sistemas operacionais e programas de aparelhos eletrônicos são escritos em C.

Veja um programa C pequeno. Ele faz uma conta simples dez milhões de vezes (somar o resto da divisão de cada número por 7) e mostra o total:

#include <stdio.h>

int main(void) {
    long long total = 0;
    for (long long i = 0; i < 10000000; i++) {
        total += i % 7;
    }
    printf("%lld\n", total);
    return 0;
}

Não se preocupe em entender cada linha agora: long long é um tipo de número inteiro grande (aula Inteiros), o for repete um trecho (aula for), o % calcula o resto da divisão (aula Operadores Aritméticos) e o %lld diz ao printf para escrever um long long (aula Formatos do printf). A Ana escreveu o mesmo programa em Python, uma linguagem interpretada:

total = 0
for i in range(10000000):
    total += i % 7
print(total)

E mediu o tempo dos dois com o comando time, que mostra quanto um programa demorou (a linha real é o tempo de relógio):

$ gcc -std=c23 -Wall -Wextra conta.c -o conta
$ time ./conta

Mesmo resultado, e o C foi uns 30 vezes mais rápido nesta conta, na máquina da Ana. Os números exatos mudam de computador para computador e de programa para programa, e o Python tem truques (bibliotecas escritas em C) para chegar perto em muitas tarefas. Mas a ordem de grandeza é essa: em contas pesadas, um programa compilado costuma ganhar com folga.

Um pouco de história

O C nasceu de um problema prático. No fim dos anos 1960, Ken Thompson e Dennis Ritchie trabalhavam no Bell Labs, o laboratório de pesquisa da companhia telefônica AT&T, nos Estados Unidos. Os dois estavam criando um sistema operacional novo, o Unix. A primeira versão foi escrita em assembly, a linguagem que é quase o código de máquina, com uma palavra para cada instrução do processador. Funcionava, mas tinha dois problemas: dava muito trabalho escrever, e o programa só servia para aquele modelo de computador. Para levar o Unix a outra máquina, era preciso reescrever tudo.

Thompson criou uma linguagem chamada B, simplificando uma mais antiga, a BCPL. Ritchie foi melhorando o B, acrescentou tipos (dizer se um dado é um número inteiro, um caractere etc.) e, em 1972, a linguagem nova ganhou o nome óbvio: a letra seguinte, C. Em 1973, o núcleo do Unix foi reescrito em C. Foi uma revolução: pela primeira vez um sistema operacional inteiro estava escrito numa linguagem que podia ser compilada para máquinas diferentes. O Unix (e o C junto com ele) se espalhou por universidades e empresas do mundo todo.

Por que o C mudou a história

Quase todas as linguagens populares de hoje copiaram a "cara" do C: as chaves { } para agrupar instruções, o ; no fim, o if (…), o for (…; …; …), o printf. C++, Java, C#, JavaScript, PHP, Go e Rust são todas "filhas" ou "netas" do C. Quem aprende C reconhece metade de cada uma delas logo de cara.

Onde o C está hoje

Mais de cinquenta anos depois, o C continua em toda parte, quase sempre escondido, fazendo o trabalho pesado:

OndeExemplos concretosPor que C

Ferramentas de programaçãoO Git, que guarda o histórico de quase todo projeto de software do mundo, foi escrito em C por Linus Torvalds em 2005. O curl (que baixa arquivos da internet, presente em bilhões de aparelhos) também é C.Tem de ser rápido e funcionar em qualquer sistema.

Bancos de dadosO SQLite, escrito em C, está dentro de todo celular Android e iPhone, dos navegadores e de milhares de aplicativos: é provavelmente o banco de dados mais instalado do mundo. O PostgreSQL e o Redis também são C.Guardar e procurar dados rápido, gastando pouca memória.

Uma língua que todas as outras falam

O C virou o "idioma comum" entre linguagens. Uma biblioteca escrita em C pode ser usada a partir do Python, do Java, do Rust, do Go e de quase qualquer outra linguagem. É por isso que bibliotecas importantes continuam sendo escritas em C: uma vez escritas, todo mundo pode usar.

Vantagens e cuidados

O C é uma ferramenta poderosa e "sem proteção", como uma faca de chef bem afiada: corta qualquer coisa, inclusive o seu dedo. Conhecer os dois lados ajuda a entender o jeito como este guia ensina.

VantagensCuidados
Velocidade: está entre as linguagens mais rápidas que existem.Sem rede de segurança: se você escrever além do fim de uma lista, o C não impede. O programa pode dar resultados errados, travar ou abrir uma brecha de segurança.
Roda em qualquer lugar: praticamente todo processador do mundo, do supercomputador ao chip de uma torradeira, tem um compilador de C.Memória à mão: quem pede memória (com malloc) tem de devolver (com free). Esquecer causa "vazamentos"; devolver duas vezes causa falhas.
Pequeno e estável: dá para aprender a linguagem inteira, e um programa escrito há 30 anos quase sempre ainda compila hoje.Pouca coisa pronta: o C não tem um tipo "texto" de verdade, nem listas que crescem sozinhas. Você aprende a construir essas coisas (o que ensina muito, mas dá trabalho).
Ensina como o computador funciona: memória, endereços, bytes. Depois do C, as outras linguagens deixam de ser "mágica".Comportamento indefinido: alguns erros não dão mensagem nenhuma; o programa parece funcionar e falha mais tarde, em outro computador (aula Comportamento Indefinido).

Os cuidados são sérios: a Microsoft e o Google já contaram que cerca de 70% das falhas graves de segurança nos seus produtos vinham de erros de memória, o tipo de erro que o C deixa acontecer. A boa notícia é que existem hábitos e ferramentas que pegam a maioria desses erros, e o guia ensina todos desde o começo: compilar sempre com os avisos ligados (-Wall -Wextra, aula Avisos), conferir o que o usuário digitou, usar as funções seguras (fgets, snprintf), e usar o -fsanitize e o Valgrind, que encontram os erros de memória por você.

C é difícil demais para começar?

O C é pequeno, e isso ajuda: em poucas semanas você conhece quase todas as palavras da linguagem. A parte difícil (ponteiros e memória) fica para o Nível 2, quando você já estiver à vontade com o resto. E existe uma vantagem enorme: quem aprende C aprende como o computador funciona de verdade, e depois qualquer outra linguagem fica mais fácil.

Quando dá errado

Ainda não escrevemos programas, mas há confusões muito comuns em quem está começando com C:

"Achei um curso de C# (ou de C++) pensando que era C"

O que aconteceu: os nomes são parecidos, mas são linguagens diferentes. O C# (lê-se "cê sharp") é uma linguagem da Microsoft, de 2000, mais parecida com o Java do que com o C. O C++ é a linguagem que nasceu do C e acrescentou muita coisa. Muito material "de C" na internet é, na verdade, C++.

Como conferir: um programa C tem #include <stdio.h> e printf, e o arquivo termina em .c. Se aparecer #include <iostream>, std::cout, cin ou class, é C++. Se aparecer Console.WriteLine, é C#.

Copiei um código C++ para um arquivo .c e o gcc reclamou

A Ana achou um "Olá, mundo" na internet, salvou como cpp.c e compilou:

$ gcc -std=c23 -Wall -Wextra cpp.c -o cpp
cpp.c:1:10: fatal error: iostream: Arquivo ou diretório inexistente
    1 | #include <iostream>
      |          ^~~~~~~~~~
compilation terminated.

O que aconteceu: o código era C++. O <iostream> é um arquivo da biblioteca do C++, e o C não o conhece. A mensagem diz "erro fatal: iostream: arquivo ou diretório inexistente" (essa parte veio traduzida, porque é o sistema que a escreve). "Fatal" quer dizer que o compilador desistiu ali mesmo, sem nem olhar o resto, e "compilation terminated" é "compilação encerrada".

Como resolver: use material de C. Em C, o "Olá, mundo" usa #include <stdio.h> e printf, como na página Início.

Um programa C que não compila como C++

"Quase todo programa C também é C++", diz muita gente. Quase. A Ana guardou o número da turma numa variável chamada class ("turma", em inglês). Em C, funciona:

$ gcc -std=c23 -Wall -Wextra turma.c -o turma
$ ./turma
A Ana está na turma 3.
$ cp turma.c turma.cpp                                   « o mesmo código, como C++
$ g++ -std=c++23 -Wall -Wextra turma.cpp -o turma
turma.cpp: In function ‘int main()’:
turma.cpp:4:5: error: expected primary-expression before ‘int’
    4 |     int class = 3;
      |     ^~~
turma.cpp:5:41: error: expected primary-expression before ‘class’
    5 |     printf("A Ana está na turma %d.\n", class);
      |                                         ^~~~~

O que aconteceu: em C++, class é uma palavra reservada (serve para criar classes), então não pode ser nome de variável. Em C, é um nome como outro qualquer. O C e o C++ são parentes próximos, mas são linguagens diferentes, com regras diferentes.

Como resolver: código C vai em arquivos .c e é compilado com gcc; código C++ vai em .cpp e é compilado com g++. Não misture os dois sem saber o que está fazendo.

"Dei dois cliques no arquivo .c e só abriu um texto"

O que aconteceu: nada de errado. O arquivo .c é só o texto do programa, o "código-fonte". Ele não roda sozinho: primeiro precisa ser compilado. Quem roda é o executável gerado pelo compilador.

Como resolver: use as caixas Experimente do guia ou instale um compilador (aulas Instalar no Linux e Instalar no Windows e macOS).

Resumo

  • Programar é escrever instruções para o computador; o processador só entende código de máquina, e alguém precisa traduzir.
  • O C é compilado: o compilador (no guia, o gcc) traduz tudo antes, e o executável roda sozinho, rápido.
  • Ele é rápido, pequeno e perto da máquina: você mexe direto na memória.
  • Criado por Dennis Ritchie no Bell Labs, em 1972, para escrever o Unix; o livro K&R é de 1978, o primeiro padrão (ANSI C) de 1989, e o guia ensina o C23.
  • Está no Linux e no Android, no Git, no interpretador do Python, no SQLite, em servidores e nos microcontroladores de aparelhos do dia a dia.
  • O preço da velocidade é a falta de proteção: erros de memória não são impedidos. O guia ensina desde o começo os hábitos e as ferramentas que pegam esses erros.
  • C, C++ e Python são linguagens diferentes: o C++ nasceu do C e é bem maior; o Python é mais fácil e mais lento, e roda em cima do C.
